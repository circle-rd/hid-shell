title: shell_child

---

`src/shell_child.nim` represents a persistent OS shell child process whose stdin/stdout are byte streams the pump marshals into HID frames. POSIX uses a pseudo-terminal; Windows drives `CreateProcessW` directly (see [Shell spawning](/hid-shell/docs/architecture/2.shell-spawning) for why).

## Types

### `ShellChild`

A reference type holding the platform-specific process state:

```nim
type
  ShellChild* = ref object
    when defined(windows):
      hProcess*: pointer    ## process handle
      hThread*: pointer     ## main thread handle (closed asap)
      hStdinW*: pointer     ## our end of child stdin (we write)
      hStdoutR*: pointer    ## our end of child stdout (we read)
    else:
      pid*: Pid
      master*: cint         ## PTY master fd (bidirectional)
```

## Procedures

### `spawnShell`

```nim
proc spawnShell*(): ShellChild
```

Return a `ShellChild` for the current OS — `spawnShellWindows()` on Windows, `spawnShellPosix()` elsewhere.

### `writeBytes`

```nim
proc writeBytes*(c: ShellChild, data: openArray[uint8])
```

Write command bytes to the shell's stdin. On Windows, a lone `CR` (`0x0D`) is translated to `CRLF` in-flight because `cmd.exe` over a pipe only commits a line on `\r\n` or `\n`; an existing `CRLF` passes through untouched. On POSIX the bytes are written to the PTY master, tolerating `EAGAIN` when the PTY is saturated.

### `tryReadBytes`

```nim
proc tryReadBytes*(c: ShellChild, buf: var seq[uint8], maxBytes: int): int
```

Non-blocking read. Returns the number of bytes read, or `0` if no data is currently available. On Windows, `PeekNamedPipe` is used to learn the buffered byte count before `ReadFile`, guaranteeing the read never blocks.

### `isAlive`

```nim
proc isAlive*(c: ShellChild): bool
```

`true` while the shell process is still running. On Windows this checks `GetExitCodeProcess` against `STILL_ACTIVE`; on POSIX it uses `waitpid(WNOHANG)`.

### `terminate`

```nim
proc terminate*(c: ShellChild)
```

Tear down the shell. On POSIX: `SIGTERM`, a 500 ms grace loop, then `SIGKILL`, then close the master fd. On Windows: close the child stdin (letting `cmd.exe` exit on EOF), wait 500 ms, then `TerminateProcess`, then close the handles.

## Platform internals

The module declares the Win32 FFI surface it needs (all `importc` from `kernel32`) — `CreatePipe`, `SetHandleInformation`, `CreateProcessW`, `PeekNamedPipe`, `ReadFile`, `WriteFile`, `GetExitCodeProcess`, `TerminateProcess`, `WaitForSingleObject`, `GetLastError`, among others — plus the POSIX libc helpers not exposed by `std/posix` in older Nim releases (`posix_openpt`, `grantpt`, `unlockpt`, `ptsname`, `setsid`).
