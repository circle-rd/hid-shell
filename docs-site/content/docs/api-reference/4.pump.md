`src/pump.nim` is the bidirectional pump: it shovels bytes between the HID link and the child shell, framing and unframing on the fly. It is a single-threaded event loop that alternates short reads from each side and never blocks indefinitely.

## Types

### `PumpStats`

Per-session counters and sequence state:

```nim
type
  PumpStats* = object
    txSeq*: uint16
    rxSeq*: uint16
    bytesIn*: uint64
    bytesOut*: uint64
```

## Constants

| Constant         | Value  | Description                                  |
| ---------------- | ------ | -------------------------------------------- |
| `ChildReadChunk` | `60`   | One HID frame payload — the read chunk size. |
| `IdlePollMs`     | `5`    | Per-read timeout for the HID link.           |
| `PingIntervalMs` | `5000` | Liveness ping period, in milliseconds.       |

## Procedures

### `runPump`

```nim
proc runPump*(link: HidLink, child: ShellChild,
              debug: proc(msg: string) = nil)
```

The main loop. Runs while `child.isAlive()`. Each iteration drains inbound HID frames (agent → host), drains child shell output (host → agent), and sends a periodic `PING`. Reassembles multi-frame `CMD` messages before writing them to the shell, and replies to `CTRL` subtypes (`PING` → `PONG`, `BYE` → return). See [The pump](/hid-shell/docs/architecture/3.pump) for the full walkthrough.

### `sendCtrl`

```nim
proc sendCtrl*(link: HidLink, stats: var PumpStats,
               subtype: uint8, extra: openArray[uint8] = []): bool
```

Send a single `CTRL` frame (always `FIN`) with the given subtype and optional extra payload bytes.

### Internal helpers

These are not exported but are used by `runPump`:

| Procedure | Description |
| --------- | ----------- |
| `nextSeq(stats)` | Return the current `txSeq` and advance it (wrapping at `0xFFFF`). |
| `sendOut(link, stats, data)` | Fragment a byte buffer into `OUT` frames of at most 60 bytes; the last carries `FIN`. |
