HID-Shell cross-compiles to three release binaries: Linux x86_64, macOS arm64, and Windows x86_64. The recommended path is the project Docker cross-toolchain, which needs nothing but Docker.

## Recommended — Docker cross-toolchain

```sh
./scripts/docker-build.sh
```

This builds the `hid-shell-builder` image (Ubuntu 26.04 base, with Nim, Zig 0.14, mingw-w64, and statically-compiled hidapi for Linux and Windows), mounts the repo into the container, and runs `scripts/build_all.sh`. Outputs land in `dist/`:

| Binary                          | Runtime dependencies on target                              |
| ------------------------------- | ----------------------------------------------------------- |
| `hid_shell-linux-x86_64`        | `libudev` (systemd, universal), libc                        |
| `hid_shell-windows-x86_64.exe`  | `setupapi.dll`, `hid.dll` (Windows built-ins)               |
| `hid_shell-macos-arm64`         | `libhidapi.dylib` — **requires `brew install hidapi` on the host** |

For an interactive shell inside the builder:

```sh
./scripts/docker-build.sh shell
```

The Dockerfile builds a `toolchain` stage that installs `nim`, `zig0.14`, `gcc-mingw-w64-x86-64`, `build-essential`, and `libudev-dev`, compiles hidapi's Linux and Windows backends to static archives under `/opt/hidapi`, and installs a `zigcc-macos-arm64` shim that pins the macOS target.

## Build a single target

`scripts/build_all.sh` accepts a target argument:

```sh
./scripts/build_all.sh linux      # or: windows | macos | all (default)
```

Environment overrides (for bare-metal runs without the Dockerfile):

| Variable        | Default                 | Purpose                          |
| --------------- | ----------------------- | -------------------------------- |
| `WIN_CC`        | `x86_64-w64-mingw32-gcc` | Windows C compiler              |
| `MAC_CC`        | `zigcc-macos-arm64`       | macOS C compiler                |
| `HIDAPI_PREFIX` | `/opt/hidapi`             | Prefix with the static hidapi archives |

## Local build (host-native only)

Requires Nim ≥ 2.0 with `nimble` and the system hidapi library:

```sh
# Debian/Ubuntu
sudo apt install libhidapi-hidraw0
# Fedora
sudo dnf install hidapi
# macOS
brew install hidapi
# Windows: drop hidapi.dll next to the built .exe
```

Then build the host-native binary only:

```sh
nimble buildRelease
```

`hid-shell.nimble` also defines `buildLinux`, `buildWindows`, and `buildMacos` tasks mirroring `scripts/build_all.sh`, with per-target size optimisation.

## Fully autonomous macOS binary (no Homebrew)

The default Docker build leaves the macOS binary linked against `libhidapi.dylib` at runtime, because hidapi's macOS backend includes `<IOKit/hid/IOHIDManager.h>` — a header from Apple's Xcode SDK that is **not redistributable** and therefore cannot be baked into the public Docker image.

If you need a macOS binary that runs on a vanilla host with nothing installed, build it on a machine that already has the Apple SDK.

### Option A — build on a real macOS host

```sh
brew install nim
curl -fsSL https://github.com/libusb/hidapi/archive/refs/tags/hidapi-0.14.0.tar.gz \
    | tar -xz -C /tmp
cd /tmp/hidapi-hidapi-0.14.0
clang -c -O2 -arch arm64 -I hidapi mac/hid.c -o /tmp/hid-mac.o
ar rcs /tmp/libhidapi.a /tmp/hid-mac.o

cd /path/to/HID-Shell
nim c -d:release -d:strip -d:hidapiStatic \
    --opt:size --threads:on \
    --cpu:arm64 --os:macosx --cc:clang \
    --passL:"/tmp/libhidapi.a -framework IOKit -framework CoreFoundation -framework AppKit" \
    --out:dist/hid_shell-macos-arm64 src/hid_shell.nim
```

The resulting binary depends only on macOS system frameworks and runs on any macOS arm64 host with nothing installed.

### Option B — `osxcross` inside the Docker image

For fully reproducible CI, extend the Dockerfile with `osxcross` and a manually downloaded Xcode `MacOSX*.sdk.tar.xz` (Apple's license forbids distributing it). Once `o64-clang` is in PATH the static build line above works inside the container too. This is left out of the default image deliberately — each developer must accept Apple's SDK license themselves.
