---
title: Debugging
description: Use --debug to trace HID-Shell, and work through the common failure modes.
---

HID-Shell is silent by design — it writes nothing to stdout/stderr unless you ask. For development and testing, pass `--debug`:

```sh
./hid_shell --debug
```

Each log line is prefixed with `[hid-shell] `. A healthy startup logs the device wait, the candidate VID/PID, the confirmation that the agent answered, and the spawned shell.

## Verifying device discovery

If the process exits with status **3**, no Vandal vendor HID was found within the wait window. With `--debug` you will see each candidate and why it was rejected:

```text
[hid-shell] candidate VID:PID 2c72:0001 path=/dev/hidg1
[hid-shell]   open failed, skipping
[hid-shell] no Vandal device among 0 HID candidate(s)
```

Common causes:

- **The agent is not plugged in**, or is on a different USB hub that the host has not enumerated yet. Increase the wait window: `./hid_shell --wait-ms 30000 --debug`.
- **Wrong device opened.** The `(0xFF00, 0x01)` usage page is shared by many devices. If the probe does not get a `HELLO_ACK`, the candidate is closed and the next one tried. If you see candidates but none is confirmed, the agent may not be the Vandal device, or its vendor interface is not up yet.
- **Permissions.** On Linux the host user must be able to open the HID device node (typically via a udev rule). `open failed, skipping` usually points here.

## Verifying the shell channel

Once connected, the pump logs `Connected; entering pump loop`. If commands are typed but never echo or run on Windows, check the input-echo path (lone `CR` → `CRLF`) — see [The pump](/hid-shell/docs/architecture/3.pump). On POSIX, a missing PTY would surface as buffered, delayed output; see [Shell spawning](/hid-shell/docs/architecture/2.shell-spawning).

## Reading HID errors

On read failure HID-Shell raises an `IOError` carrying hidapi's last error string (`hid_error`). On Windows this surfaces the underlying `GetLastError()` text, which is the key diagnostic when `ReadFile`/`WriteFile` fail (for example `ACCESS_DENIED`, `INVALID_USER_BUFFER`, `DEVICE_NOT_CONNECTED`). A Windows read buffer must be sized `FrameSize + 1` — passing only `FrameSize` makes `ReadFile` fail with `ERROR_INVALID_USER_BUFFER`.

## Unplugging the device

If the USB device is pulled while the pump is running, the next `readFrame` either times out or raises; the pump exits and `main` closes the link. Killing the process (`SIGKILL`) also terminates the child shell via the `finally` block in `main`.
