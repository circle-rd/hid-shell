HID-Shell is a small, focused Nim project. Contributions are welcome — this page points at the layout and the conventions the code follows.

## Repository layout

```text
HID-Shell/
├── hid-shell.nimble          # nimble manifest (name, deps, build tasks)
├── Dockerfile                # cross-compilation toolchain stage
├── docs/
│   └── PROTOCOL.md           # protocol reference (this site is authoritative)
├── scripts/
│   ├── build_all.sh          # build the three release binaries
│   └── docker-build.sh       # wrap the Docker toolchain build
├── src/
│   ├── hid_shell.nim         # entrypoint / argument parsing / lifecycle
│   ├── protocol.nim          # frame constants + encode/decode
│   ├── transport_hid.nim     # device discovery + raw frame I/O
│   ├── shell_child.nim       # platform shell spawn + byte-stream API
│   ├── pump.nim              # the bidirectional event loop
│   └── hidapi_ffi.nim        # minimal hidapi FFI bindings
└── .github/workflows/
    └── publish-binaries.yml  # cross-compile + attach binaries to a release
```

## Conventions

- **Code is truth.** The protocol and behaviour are defined by the source. If `docs/PROTOCOL.md` and the code disagree, the code wins (and the doc should be fixed).
- **Cross-platform correctness is explicit.** Platform differences (PTY vs Win32, lone-CR handling, report-ID byte) are concentrated in `shell_child.nim` and `transport_hid.nim` with comments explaining *why*. Preserve that reasoning when you touch those paths.
- **Headless by default.** Do not add stdout/stderr output outside the `--debug` path.
- **Size matters.** The build flags (`--opt:size`, `--gc-sections`, stripped metadata) exist to keep the payload small. Don't add dependencies or runtime features casually.

## Building for development

The fastest loop is the Docker toolchain:

```sh
./scripts/docker-build.sh shell   # interactive shell with the toolchain
```

Or build the host-native binary directly:

```sh
nimble buildRelease
```

## Reporting issues

Report bugs on the [GitHub issues tracker](https://github.com/circle-rd/hid-shell/issues). Include the host OS, the agent firmware version, and (if available) a `--debug` transcript.
