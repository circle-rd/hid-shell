title: Introduction

HID-Shell is a **headless shell payload** written in Nim. When a [Vandal](https://github.com/circle-rd) ESP32 agent is plugged into a USB host, HID-Shell connects to the agent's **vendor HID interface** and opens an interactive shell on that host — streaming bytes to and from the agent over raw 64-byte HID reports.

It is the payload side of the shell channel that the Vandal web UI presents as the *Shell* page. You type a command in the web UI, the agent forwards it over HID, HID-Shell feeds it to a local shell, and the output travels back the same way.

## What it does, in order

On launch a single HID-Shell binary:

1. **Finds the agent.** It enumerates every HID device on the host, narrows to the ones advertising the Vandal vendor usage `(0xFF00, 0x01)`, then **probes** each candidate with a `HELLO` frame to confirm it is actually the Vandal agent — not an RGB controller, gaming dongle, or hobbyist board that happens to share the vendor usage page.
2. **Spawns a shell.** `cmd.exe` on Windows (with no console window), or an interactive `/bin/sh` attached to a pseudo-terminal on Linux and macOS.
3. **Pumps bytes.** A single-threaded loop shovels command bytes from the agent into the shell and shell output back to the agent, framing each 60-byte chunk into a HID report.
4. **Stops** when the agent sends `BYE`, the USB device disappears, or the process is killed.

## When to use it

- You need an interactive shell on a USB host through a Vandal agent, with **no network path** available and **no console window** that would alert the operator.
- You want a small, statically-linkable, cross-compiled binary (Linux x86_64, macOS arm64, Windows x86_64) that runs with minimal host dependencies.

## When not to use it

- **HID-Shell is a payload, not a stand-alone application.** It does nothing useful without a Vandal agent providing the HID channel. It is normally launched by the agent's universal BadUSB launcher, not by hand.
- It is a **single-purpose v1 shell bridge**. It is not a general-purpose HID stack, a reverse-proxy shell server, or a remote-management tool. For those, use the corresponding Vandal agent modules.

## Headless contract

HID-Shell is built to be invisible on the target host:

- **Windows** — compiled with `--app:gui` so the Windows console subsystem does not allocate a visible window for the child `cmd.exe`.
- **POSIX** — the payload does not write to stdout/stderr unless you pass `--debug`. The launcher disowns the process so it survives the terminal that started it.
- **All shell I/O travels over HID.** Nothing is written to disk by HID-Shell itself.

## A note on the protocol documentation

The repository ships a [`docs/PROTOCOL.md`](https://github.com/circle-rd/hid-shell/blob/main/docs/PROTOCOL.md) file. This site is the **authoritative** description of the wire protocol. Where the two differ, the description here (and in the [Wire protocol](/hid-shell/docs/protocol/1.wire-protocol) reference) reflects what the code actually transmits — in particular, the payload length is encoded in the high bits of the frame's `flags` byte, not left as a fixed 60-byte payload.
