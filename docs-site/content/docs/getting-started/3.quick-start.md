title: Quick start

There are two ways HID-Shell actually gets run: by hand (useful for development and testing against a plugged-in agent), or by the Vandal agent's universal launcher (the real deployment path).

## Run manually

With a Vandal agent plugged in, launch the binary directly:

```sh
./hid_shell                # auto-detect the device, headless
./hid_shell --debug        # log each stage to stderr
```

A typical `--debug` run looks like this:

```text
[hid-shell] starting; waiting up to 20000 ms for device
[hid-shell] candidate VID:PID 303a:4001 path=/dev/hidg0
[hid-shell]   -> Vandal agent confirmed
[hid-shell] opened device /dev/hidg0 (VID:PID 303a:4001)
[hid-shell] spawned shell pid=4242
[hid-shell] Connected; entering pump loop
```

### Command-line options

| Option        | Description                                                                 |
| ------------- | --------------------------------------------------------------------------- |
| `--help`, `-h` | Print usage and exit.                                                        |
| `--debug`     | Log each stage to stderr. Without this the process is silent by design.     |
| `--once`      | Exit after the first shell session ends (the default behaviour today is to exit after one session). |
| `--wait-ms N` | How long to wait for the device before giving up, in milliseconds. Default `20000`. |

The default 20 second wait exists because Windows can be slow to surface a freshly-mounted composite device's vendor HID interface, especially on first driver bind. It gives comfortable headroom while still failing fast on a genuinely absent agent.

If no Vandal vendor HID is found within the wait window, the process exits with status **3**. Unknown options or unexpected arguments exit with status **2**.

## The standard deployment loop

In production the binary is **not** invoked by hand. The flow is:

1. The agent streams the universal DuckyScript launcher inline (~2 KB, a single MQTT message).
2. The agent injects it as HID keystrokes; the launcher execs the matching `/payloads/sl` / `sm` / `sw.exe` silently.
3. HID-Shell connects, spawns the shell, and the pump loop comes up.
4. From the agent's *Shell* page the operator clicks **Prepare** → **Start**, then types commands.
5. Clicking **Stop** makes the agent send `BYE`; HID-Shell tears down the shell and exits.

In v1 the session is one-shot per payload run — the next click in the UI relaunches a fresh process. A `--reattach`-style persistent mode is noted in the source as future work.
